# Ascend Performance — revised V1 delivery sequence

Updated September 29, 2026 after Phase 7 implementation.

The original concept grouped Foundation, Training Intelligence, Fuel + Body, Recovery and Aethelios intelligence into five broad areas. Implementation phases 1–4 split the training foundation into smaller deliverables. They did not complete all five original areas. The sequence below is a new planning estimate, not a claim that this exact numbering was previously approved.

| Phase | Outcome | Exit criteria |
| --- | --- | --- |
| 1 — Built | Foundation and recording | Owner-bound training/check-in records; offline workout retention and sync |
| 2 — Built | Programs and session preparation | Versioned cycles; explicit shorter/lighter acceptance; immutable session prescriptions |
| 3 — Built | Progression review | Evidence-bound proposals; explicit approval; atomic saved decisions |
| 4 — Built | Decision outcomes | First two subsequent attempts, actual values, revision boundaries and retained evidence |
| 5 — Built | Fuel & Body | User-set reference targets; focused daily capture; complete/partial distinctions; normalized weight trends |
| 6 — Built | Recovery & sleep | Usable sleep/recovery routine, longitudinal self-report context, explicit next-day choices and outcomes without a fabricated readiness score |
| 7 — Built | Movement & broader training | Exercise identity/library, reviewed substitutions and progression settings; cardiovascular and mobility recording, with appropriate units and separate evidence rules |
| 8 — Remaining | Physical Twin V1 + integrated intelligence | Unified, source-labeled physical profile; training/fuel/recovery/movement review; appropriate whole-man summary and opt-in Aethelios interpretation; unknowns stay visible |
| 9 — Remaining | V1 integration & release | Data lifecycle/export/corrections, mobile interaction integration, accessibility, real-account/device tests, shared-ledger migration reconciliation and approved rollout |

**After Phase 7: two core phases remain in this revised V1 plan.** Each can contain implementation tasks; material scope changes should update this table explicitly rather than silently extending the sequence. Phases 1–7 remain unreleased until migrations and release gates are satisfied. A scoped founder beta can happen earlier if the founder authorizes release and its gates pass.

The larger flagship vision is a separate expansion program: native Health Connect/HealthKit and wearables; food-source integrations and richer meal workflows; physiological model calibration; advanced 3D body visualization; camera/form analysis; longitudinal experiments and coach/professional workflows. Their count cannot honestly be fixed before feasibility, data-quality and device research. V1's Physical Twin is a sourced, evolving physical profile, not a validated simulator or photorealistic body prediction.

The app-wide UX upgrade is being planned separately. Performance should adopt that approved interaction system during integration rather than impose an independent shared-shell redesign in this phase.
