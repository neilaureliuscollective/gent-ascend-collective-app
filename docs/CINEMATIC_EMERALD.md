## Implementation decisions

- Keep Next.js server-rendered public content and existing routing. Client islands own presentation only; public visual code reads no private records.
- One public-layout director observes visible sections and batches native scroll measurements before CSS variable writes in a requestAnimationFrame. It does not intercept wheel/touch, hide copy before hydration, or install a perpetual animation loop. Route changes clean up observers/listeners. This small choreography does not warrant another animation library; complex future pinned timelines can justify one later.
- Emerald (#0B3B32) becomes the dominant material, with brighter green light, gold edges and depth. Public CSS remains isolated from the OS.
- Homepage: dimensional world portals; product atelier; spatial intelligence rings/grid; opening Reserve architectural panels; statement and invitation treatments. Subpages inherit material, lighting and scroll composition.
- Native anchor chapter navigation remains usable without JavaScript. Still mode spans routes within the public layout and honors OS reduced motion. Film honors the global control too. Full content remains visible without JS.
- Three.js is already installed. Dynamically import the product renderer only after the visitor chooses Explore in 3D. This is a procedural **packaging study**, not a final bottle model, product specification or purchasable variant. It is explicitly labeled next to the experience.
- The renderer has no automatic spin. Pointer/keyboard rotation, lighting choices, reset and resize request frames; hidden/offscreen scenes do not render. DPR capped at 1.5; low-power context; dispose GPU resources on removal/context loss. No physics, postprocessing, remote assets or photo upload.
- A CSS vessel is present before JS and remains when WebGL fails. No unsupported device blocks content/navigation. The 3D shape can later be replaced with an approved GLB behind the renderer boundary.
