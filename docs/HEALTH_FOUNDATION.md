# Aethelios Health — approved first-build implementation

Founder approved the records-first specification on October 12, 2026. Canonical repository only: `neilaureliuscollective/gent-ascend-collective-app`. Baseline main/production source at audit: `c0a7f35f9de0b314703814667bce82a79133adea`. Implementation branch: `feat/health-intelligence-foundation`. No second application, production merge, hosted migration, activation or deployment.

## Delivered implementation

Six first-class routes: `/app/health`, `/history`, `/records`, `/labs`, `/connections`, `/privacy` under the same Health prefix. Shell navigation and Ecosystem discover Health. Imperial Obsidian materials, official shared shell, native ContextSheet dialogs, static decorative geometry, source inspector tables, small-screen composition, reduced motion and forced colors. Global general-conversation and capture controls are excluded from Health surfaces. Optional Web Vitals excludes Health routes, including SPA entry. No mock personal-mode readings, readiness score or body simulator.

Health Command reads existing Performance check-ins/movement only under current wellness permission. Sleep duration, weight, dated energy/soreness self-reports and recorded movement remain distinct. Original minutes/weight units accompany converted displays. Source day, saved time, version, actual date gaps and unavailable sections stay visible. Existing Recovery/Fuel/Training workflows remain authoritative; Health does not duplicate or mutate them.

Private schema/RLS, session-bound owner RPCs and an immutable separate `aethelios-health` Storage bucket. A server flag alone cannot activate ingestion: database activation defaults off and is not member/service-role writable. Trusted existing founder/beta eligibility (not paid membership), adult self-attestation, recent Auth sign-in for sensitive grants/export/deletion, ownership in every mutation, a client-context/verified-person mismatch guard before mutation/export, revoked direct table writes, bounded inputs and quotas.

Original PDF/JPEG/PNG files are private attachments; no embedded viewer or active PDF execution. CSV/JSON supports 1–100 reported results per import and 200 KB text. Originals have an 8 MB limit, vault 200 records/50 MB total, confirmed observations 2,000. File signatures, stored-object re-read and SHA-256 verification precede finalization. Same-file retries preserve deterministic candidate IDs. Exact content duplicates are denied per owner. Interrupted reservations are visible and removable.

PDF extraction is deliberately narrow: only the tested Aethelios Lab Exchange v1 form layout with `aethelios_lab_exchange_version=1` and a JSON array in `aethelios_lab_exchange_json`. Ordinary/scanned reports remain originals without inferred results. No general OCR, real lab-vendor template integration or FHIR import is claimed. Existing pinned pdf-lib is reused; no dependency added. Parser runs in a separate V8 worker heap with a 128 MB old-generation ceiling, input/text/page limits and enforced 10-second termination. This is a bounded worker, not an OS security sandbox or a complete RSS ceiling. Node/Vercel worker lifecycle is a hosted acceptance gate. Deployment traces include worker and library dependencies.

Lab review shows concise result summaries with expandable correction fields, followed by explicit confirmation. Preserve original test/code/value/unit/specimen/method/reference-range/flag and collection date. Codes are reported, never guessed or certified as valid LOINC mappings. No lab unit conversion or universal optimal ranges. Numeric differences require matching meaning/unit/method/specimen, dated numerical values and no same-date conflicts. Qualitative/comparator results remain visible without numerical inference. Amendments are versioned with reasons; exclusions preserve originals/revisions. Affected AI explanations are invalidated.

Health-only conversation has its own turns, evidence snapshots and consent version. No general memory/history, Council, business context, search tools, write tools or clinical actions. A bounded direct OpenAI request (45 seconds, zero retries, 1,000 output tokens, 10 reservations/day) is independently gated. `store:false` is not a zero-retention guarantee. Evidence/consent are rechecked before dispatch and before completion; an already dispatched disclosure cannot be recalled. Questions, pending/failed/completed answers and source selection are visible without a fabricated save acknowledgment. No live provider call or medical-safety evaluation is claimed.

Private streamed JSON export (bounded original chunks and renewable lease, avoiding a buffered response-size ceiling) includes base64 originals, records, observations, consent, all retained conversation turns, revisions, processing receipts and scalar quota reservations. Deletion marks records unavailable, removes originals through the owner's Storage session, verifies no originals remain before completion, cascades observations/revisions, clears Health conversation and sensitive retry payloads. Versioned consent withdrawal and deletion tombstones prevent late saves/resurrection. Lost deletion acknowledgments replay through durable job receipts. Existing Performance data is independently owned and is not deleted by Health-only deletion.

Export/deletion jobs use owner-bound two-minute leases. They resume through authenticated requests; there is no registered unattended scheduler or privileged general user-data worker. Failed jobs remain resumable after lease expiry. Export retries may regenerate a current private snapshot after completion rather than retaining another sensitive export artifact. Deletion tombstones must survive/replay before exposing any restored backup. Scalar AI quota reservations contain no medical content and age out on the next reservation after 30 days; they remain through content deletion to prevent quota-reset abuse. Legal retention/backup policies remain activation prerequisites.

## APIs and module ownership

`GET /api/health`: current private snapshot and independently degraded wellness sections. `POST /api/health`: strict discriminated mutations, bounded same-origin multipart upload and exact-request recovery. `GET /api/health/records/:id`: authenticated attachment retrieval, no-store, nosniff, sandbox and no-referrer. `POST /api/health/export`: recent-auth private export. Private read/export RPCs never expose the private schema through the Data API.

Domain modules: `schema.ts`, `service.ts`, `imports.ts`, `pdf.ts`, `trends.ts`, `conversation.ts`. Page composition owns no business rules. Reused identity/person mapping, Supabase session client, Performance conversion/calendar semantics, shell, native dialogs, HTTP validation and existing tests. Manual Database RPC contracts describe the migration; CLI-generated types remain a real-local-schema acceptance task.

## Activation and release gates

`HEALTH_INGESTION_ENABLED` and `HEALTH_AI_ENABLED` default absent/off. Optional `HEALTH_AI_MODEL` uses the existing direct OpenAI arrangement. No key replacement, billing change or provider connection has occurred. Database `health_private.activation` must be reviewed by an operator on protected staging before either capability is accepted; never enable it automatically in migrations or seed production data.

Before sensitive production beta: reconcile shared hosted migration history and functions/grants; audit Reserve/service/admin credentials and exposed schemas; confirm processor contracts and real retention configuration; approve consumer-health policy, deletion/backup schedule and incident response; validate two-account hosted Auth/Storage and reauthentication; verify worker tracing/runtime and crash recovery; review actual iPhone/Fold/desktop visuals, screen readers, keyboard, zoom/contrast and downloads. Use adult owner-only beta; membership never authorizes clinical care. If shared-project privileged isolation is inadequate, a separately secured storage boundary is required while preserving the single unified app.

Research supports the recorded decisions: [HealthKit authorization](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data), [Health Connect reads](https://developer.android.com/health-and-fitness/health-connect/read-data), [SMART 2.2](https://hl7.org/fhir/smart-app-launch/STU2.2/app-launch.html), [FHIR Observation](https://hl7.org/fhir/R4/observation.html), [LOINC](https://loinc.org/start), [UCUM](https://ucum.org/ucum), [FDA wellness guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/general-wellness-policy-low-risk-devices), [FTC Health Breach Notification Rule](https://www.ftc.gov/legal-library/browse/rules/health-breach-notification-rule), [OpenAI retention](https://developers.openai.com/api/docs/guides/your-data), [Supabase Storage RLS](https://supabase.com/docs/guides/storage/security/access-control). Checked during the October 12 audit. Supabase changelog retrieval failed; no assertion of fetched changelog compatibility is made.

Future: one proven cloud wearable, broader extraction, native HealthKit/Health Connect bridge, one patient-authorized FHIR provider, then richer sourced Physical Twin. No physiology simulation, universal provider connectivity or clinical program is promised.

Do not grant access using an email, cookie, client metadata or paid tier. This intentional local setup is independent of production onboarding/payment and never runs against hosted projects. The synthetic Health SQL tests create a trusted founder assignment in their isolated test database; the ordinary seed and historical authority tests remain unchanged.
