# Ascend Journey · Phase 5 (2026-09-27)

The last public door now opens a real member entrance at `/enter`. Signed-out visitors see the same Gent Ascend materials and crest with a private invitation sign-in form when Auth is configured. The disconnected preview clearly says accounts are unavailable there. Verified signed-in visitors see a direct path to their personal space or to confirm their invitation. The invited member welcome echoes the crest and material language before the existing first-session steps. Shop and the public journey remain one click away.

The experience reuses the public layout, existing server-side session, password action, private pilot claim and workspace. Auth status is server-rendered, `/enter` is dynamic and noindexed, and the existing proxy marks it private/no-store. The form marker chooses only a fixed local error destination. It grants nothing. The secure invitation link still goes directly to `/app/welcome`, and successful password sign-in still routes to Command or welcome based on existing member state. There is no new account creation, third-party login, booking or data migration.

The visual entrance uses CSS rings and a short optional reveal. Reduced motion receives the same complete content without animation. It has no new renderer, model, heavy media or dependency. The primary product boundary remains intact: the personal dashboard and private data are under `/app`.

Verification: lint, strict types, 84 unit tests and production build pass; targeted public/brand/invitation browser checks pass at 344, 768 and 1440 CSS pixels in software-rendered Chromium, including reduced motion and overflow. Rendered entrance captures at those widths were inspected. The local Supabase founder browser gate (valid session and rejected credentials) and the full CI suite run on the draft PR. Physical Fold, iPhone Safari, keyboard/password manager and field performance remain release review items. This build is not a production promotion.
