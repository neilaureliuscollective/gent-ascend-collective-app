## Implemented slice

Public `/app/business-connections` connects an owned company room to an explicitly chosen professional. With separate optional website consent, it reads registered website copy and at most ten service descriptions. Katie can ask the existing Aethelios engine for wording, with per-reply consent. Source version/timestamp is saved with the company turn. The reply remains a draft; Katie reviews/copies the chosen wording into editable fields, then explicitly saves a proposal. No model tool can publish, change code, write prices or edit appointments.

Reserve holds a thin website-to-provider registry and immutable proposals/baselines. The existing provider-brands table remains the single draft/published presentation source; existing saveBrand/publishBrand validation, identity rules, asset checks and actor/revision events are reused inside the same approval transaction. Approved proposals retain exact copy history. First reference: `fix-it-shop` → provider `katie` → existing `/fix-it-shop`; no new branded app, AI engine, payment system or hosting service. Editable fields are the hero introduction, founder/about paragraph (existing brand bio) and descriptions of the professional's existing services. React renders plain text; arbitrary HTML, scripts, paths, contact data, prices, duration, branding assets and booking rules are outside the API contract.

Reserve `/studio/websites` displays exact current/proposed wording and service changes. Katie prepares and reviews drafts; the existing Reserve owner separately approves/rejects the immutable saved proposal. This preserves the provider branding studio's owner-only publication rule. Assigned professionals can view their own provider's approval queue but cannot approve it. Approval locks the existing brand, verifies the displayed baseline version and every affected service revision, then updates all approved fields and records brand events/proposal history in one transaction. An unreviewed competing Brands draft is never overwritten; it must be reviewed first. Stale/duplicate approvals cannot overwrite later work. Copy publication uses the existing dynamic public page; no deployment is needed per approved content change. A rejected/saved proposal has no public effect. Disconnection does not erase earlier drafts/history; publication still requires independent local authority.

Proposals are idempotent for the same UUID, account, grant and exact input fingerprint. An uncertain browser save locks editing/resubmission until current receipts are reloaded. Maximum 30 proposals in the outstanding/recent-day queue per website; source payloads and models remain bounded by the existing broker/AI quotas. Old wording can be restored by a fresh reviewed proposal; this slice does not implement a one-click rollback.
